# M2.8 question tasks and browser contract

Approved P-029, baseline 29b308978783d3f214174900eb1ed84f1919b4cf.

POST /api/questions takes conversation_id, request_id, question, document_ids.
M3/P-031 adds optional previous_question_id; see [temporary memory contract](m3-memory-contract.md).
It returns 202 with question_id, frozen request and task status. Same conversation /
request ID and normalized content returns the same task; changed content returns
409 request_conflict. Validate all selected documents before admission/model calls.
The existing strict question limits apply. Idempotency lasts for task retention only.

GET /api/questions/{id}?conversation_id=... returns queued/running/completed/failed,
stage, creation/deadline epoch timestamps and either a full answer or fixed error.
Unknown, expired and other-conversation IDs return 404. Conversation IDs isolate
demo state; they are not authentication or a multi-user authorization system.
Stages: queued, planning, retrieving, querying_csv, waiting_rate_limit, generating,
calculating, validating, completed/failed. No synthetic percentages or SLA.

QuestionTasks owns a single worker, at most 8 waiting tasks, 1000 retained tasks and
24-hour temporary retention. SQLite is accessed by the backend only. Queue/storage
capacity errors return 503. Completion does not rely on HTTP remaining connected.
A monitor and reads enforce the shared 240s monotonic budget including queueing;
publication updates only running tasks, so late workers cannot overwrite failure.
Expired work may still occupy the one worker until its bounded provider I/O returns.
Shutdown/startup marks unfinished tasks interrupted; no automatic re-execution.

GET /api/questions/{id}/csv/{tool_index}?conversation_id=...&offset=0&limit=20
reuses that completed question's original CSV order IDs and frozen document scope.
Limit 1–100, nonnegative offset; no model call, no extra user-supplied query or scope.
This returns records and counts from immutable ready documents. It does not regenerate
the answer or promote newly browsed rows into the original citation set.

Browser: per-tab temporary conversation/request metadata supports refreshing and
resuming GET polling without automatic POST resubmission. No cross-conversation
history goes to the server/model. A new conversation starts with empty turns/scope.
M3/P-031 enables bounded same-conversation reference resolution with fresh scoped evidence;
long-term chat history remains out of scope. Conversation retention is fixed from its first turn.
Only a user-triggered resend of the same submission can recover an ambiguous POST;
the request ID and original content stay unchanged. Terminal retry is a new request.

Visual direction extends existing Segoe UI, white background, ink #263443,
muted #626e79, line #dce2e8, accent #155b91 and surface #f3f6f8. Keep left-aligned
readable question/answer rows, inline expandable sources and the existing composer
and upload/sidebar placement. No HTML generated by the model is interpreted.

Approved tests cross actual task storage/HTTP, controlled external model/time and
browser interactions. Separate real smoke uses a new Compose project/empty D-drive
runtime, backend runtime-only keys, fresh PDF/CSV uploads/indexes/answers. A pinned
tokenizer is infrastructure, not a development index. Two successful paths do not
replace M3 multi-document/state/failure acceptance or M2 final Standards/Spec review.
